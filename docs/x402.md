# x402 Payment Integration — Research & Design (Group 9)

Findings researched from the **official x402 documentation and SDK** (do not guess — design
note b). Provenalt uses the official `x402` Python SDK for all protocol-format-sensitive
parts (schemas, price→asset resolution, facilitator verify/settle) rather than hand-rolling
headers or payloads.

## Sources

- x402 facilitator concept — https://docs.x402.org/core-concepts/facilitator
- x402 protocol / SDK (schemas, FastAPI middleware, examples) —
  https://github.com/coinbase/x402 (`python/x402`, `examples/python/servers/fastapi`)
- Coinbase CDP facilitator (fee-free USDC on Base) — https://docs.cdp.coinbase.com

## The seller flow (four steps)

1. Client makes a normal HTTP request to a gated endpoint.
2. Server responds **HTTP 402** with a `PaymentRequired` body listing acceptable payment
   terms (`accepts: [PaymentRequirements]`).
3. Client retries with an `X-PAYMENT` header carrying a signed payment payload (for the
   EVM `exact` scheme, an EIP-3009 `transferWithAuthorization` over USDC).
4. Server **verifies** the payload with a facilitator (`/verify`), fulfills the request, then
   asks the facilitator to **settle** it on-chain (`/settle`), and returns 200 with an
   `X-PAYMENT-RESPONSE` header (settlement info). The facilitator sponsors gas and never
   custodies funds.

## Exact wire format (from the SDK, verified offline)

402 body (`PaymentRequired`, camelCase via alias):

```json
{
  "x402Version": 1,
  "error": "X-PAYMENT header is required",
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "amount": "10000",
      "payTo": "0x…receiving wallet…",
      "maxTimeoutSeconds": 60,
      "extra": { "name": "USD Coin", "version": "2" }
    }
  ],
  "extensions": {}
}
```

- **Network:** `eip155:8453` = Base mainnet (`eip155:84532` = Base Sepolia).
- **Asset:** the SDK resolves `$0.01` → USDC. On Base mainnet that is
  `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`, amount `10000` (6 decimals).
- The client sends the signed payload in the `X-PAYMENT` header; the server returns
  `X-PAYMENT-RESPONSE` on success.

## Facilitator

- **Verify/settle** happen against a facilitator. The public `https://x402.org/facilitator`
  supports **testnets**; **Base mainnet requires the Coinbase CDP facilitator** (CDP API
  credentials). This is configured via environment, never committed.
- The SDK `x402ResourceServer.initialize()` queries the facilitator's supported
  scheme/network set; so building live 402/verify/settle needs a reachable facilitator.

## How Provenalt integrates it

Provenalt applies x402 as a **custom gate middleware** (`services/api/provenalt_api/x402_gate.py`)
on the gated tier — `GET /v1/agents/{id}/score`, `GET /v1/provenalt/{id}`, `GET /v1/eligibility`
(proposal §7). The free tier (Group 6) is unchanged.

Per request on a gated route:

1. A valid partner `X-API-Key` **bypasses** payment (as it bypasses rate limits) — metered as
   `api_key`.
2. If x402 is not configured (no receiving wallet), the gate does not charge (dev/test) —
   metered as `unpaid_open`.
3. Otherwise, with no `X-PAYMENT` header the gate returns a spec-correct **402** built from the
   SDK schemas (offline). With an `X-PAYMENT` header it **verifies + settles** via the SDK
   facilitator (production), then meters the call with the payer address, amount, and tx hash.

The 402 body is built from the official `PaymentRequirements`/`PaymentRequired` models and the
`ExactEvmServerScheme` price parser (so headers/asset/amount are authoritative, not guessed).
Verify/settle use `x402ResourceServer.verify_payment` / `settle_payment` — exercised only in
production against a real facilitator.

## Configuration (environment — never committed)

| Variable | Meaning |
|---|---|
| `PROVENALT_X402_ENABLED` | Turn payment enforcement on (default off). |
| `PROVENALT_X402_PAY_TO` | Receiving wallet address (required when enabled). |
| `PROVENALT_X402_NETWORK` | CAIP-2 network, default `eip155:8453` (Base). |
| `PROVENALT_X402_PRICE` | Price string, default `$0.01`. |
| `PROVENALT_X402_FACILITATOR_URL` | Facilitator base URL (Base mainnet → CDP). |

Pricing starts at **$0.01/call in USDC on Base**. Partners use `X-API-Key` to bypass.
